# GitHub PR Workflows

End-to-end GitHub pull request lifecycle: review, comment, and close PRs from Shoal sessions.

## Overview

Shoal's GitHub integration enables:

- **Spawn review sessions** with full PR context (diff, comments, files changed)
- **Post review findings** back to GitHub as PR comments
- **Close the loop** with handoff generation and PR finalization

## Commands

### List PRs

```bash
# List all open PRs in a repo
shoal github ls-prs --repo owner/repo

# Filter by state
shoal github ls-prs --repo owner/repo --state closed
```

### Start from PR

```bash
# Create a session from a PR
shoal github start-pr owner/repo 123
```

Creates a session with:
- Session name derived from PR title
- Branch checked out to PR head
- Worktree isolated from main

### Review a PR

```bash
# Spawn a review session with full context
shoal github review-pr owner/repo 123
```

**What happens:**

1. Fetches PR metadata (title, description, author, labels)
2. Pulls the full diff
3. Retrieves all review comments and threads
4. Spawns a reviewer session (uses `pantheon-review` template if available)
5. Injects context as a prompt file

**Session receives:**

```markdown
# PR Review Context

**PR**: #123 — Add authentication middleware
**Author**: @username
**Branch**: feat/auth-middleware

## Description
[PR description content]

## Files Changed
- src/middleware/auth.py (+145, -0)
- tests/test_auth.py (+89, -0)

## Diff
[Full unified diff]

## Existing Comments
[All review threads with line numbers]

Your task: Review this PR for correctness, security, and style.
```

### Post Review Findings

```bash
# Post session findings back to GitHub
shoal github post-review owner/repo 123
```

**What happens:**

1. Reads the session journal
2. Extracts review findings (from journal entries or handoff)
3. Posts as a GitHub PR comment
4. Attributes the comment to the Shoal bot/user

**Example posted comment:**

```markdown
## 🤖 Shoal Review Findings

**Session**: review-auth-middleware-123
**Reviewed by**: omp (Claude Sonnet 4.6)

### Issues Found
- [ ] L145: Potential SQL injection in user lookup
- [ ] L89: Missing test coverage for expired tokens
- [ ] L102: Hardcoded secret should be env var

### Recommendations
- Add parameterized queries for all DB access
- Expand test suite to cover edge cases
- Move secrets to environment variables

---
*Generated by [Shoal CLI](https://github.com/TheShoal/shoal-cli)*
```

### Finalize PR

```bash
# Post handoff and close the PR workflow
shoal github done-pr owner/repo 123
```

Combines handoff generation with PR finalization:

1. Generates handoff artifact
2. Posts handoff summary as PR comment
3. Optionally merges the PR (if `--merge` flag provided)

## Full PR Review Workflow

### 1. Start Review

```bash
shoal github review-pr owner/repo 123
```

This spawns a dedicated reviewer session.

### 2. Agent Performs Review

The agent (Claude Code, omp, etc.) has access to:

- Full PR diff
- All existing comments
- File tree of changes
- PR metadata

It writes findings to the session journal as it works.

### 3. Post Findings

```bash
shoal github post-review owner/repo 123
```

Shoal reads the journal and posts structured findings to GitHub.

### 4. Close the Loop

```bash
shoal github done-pr owner/repo 123
```

Generates handoff and finalizes the review session.

## Integration with pantheon-review Template

If you have a `pantheon-review.toml` template configured:

```toml
[template]
name = "pantheon-review"
tool = "omp"
description = "Code review session optimized for PR analysis"

[template.env]
REVIEW_MODE = "strict"
FOCUS_AREAS = "security,performance,correctness"

[[template.windows]]
name = "review"
panes = [
  { command = "omp" }
]
```

The `review-pr` command will use this template, giving the agent review-specific context and configuration.

## Configuration

### GitHub Token

Set in `~/.config/shoal/config.toml`:

```toml
[github]
token = "ghp_..."  # GitHub personal access token
```

Or as an environment variable:

```bash
export GITHUB_TOKEN="ghp_..."
```

### Repository Shortcuts

In `.shoal/workspace.toml`:

```toml
[github]
default_org = "myorg"

[github.repos]
backend = "myorg/backend-api"
frontend = "myorg/frontend-app"
```

Then use shorthand:

```bash
shoal github review-pr backend 123
# Expands to: myorg/backend-api
```

## Common Patterns

### Parallel Reviews

```bash
# Review multiple PRs in parallel
shoal github review-pr owner/repo 101
shoal github review-pr owner/repo 102
shoal github review-pr owner/repo 103

# Each runs in isolated worktree
shoal ls --tree
```

### Reviewer + Implementer Pair

```bash
# Start a session to address review feedback
shoal github start-pr owner/repo 123

# Spawn a reviewer to audit the fixes
shoal github review-pr owner/repo 123

# Both agents coordinate via Agent Bus
```

### Automated Review Posts

```bash
# Review, post, and close in sequence
shoal github review-pr owner/repo 123 && \
shoal github post-review owner/repo 123 && \
shoal github done-pr owner/repo 123
```

## Error Handling

| Error | Cause | Solution |
|-------|-------|----------|
| "GitHub token not found" | Missing token config | Set in config.toml or env |
| "PR not found" | Invalid PR number | Check repo and PR number |
| "Permission denied" | Token lacks repo scope | Regenerate token with `repo` scope |
| "Rate limit exceeded" | Too many API calls | Wait or use authenticated token |

## Best Practices

1. **Use review template**: Configure `pantheon-review` for consistent review context
2. **Post findings incrementally**: Don't wait until review is complete
3. **Tag review sessions**: Use `--tag review` for easy filtering
4. **Archive after merge**: Kill review sessions once PR is merged
5. **Audit bot comments**: Review what Shoal posts before --post flag
